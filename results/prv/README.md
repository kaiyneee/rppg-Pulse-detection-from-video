# Вариабельность пульса: замер онлайн-цепочки и офлайн-цепочка

Без выводов о том, какой вариант лучше, — только числа и факт проверок.

## Параметры (зафиксированы до прогона)

Записаны в `params.json` в 2026-10-15T14:32:52+00:00 — до первого расчёта.

- Конфигурация пайплайна: fft_spectral_mean (умолчание).
- Сопоставление ударов: один к одному, пары по возрастанию |Δt|, допуск ±150 мс.
- Отрезок оценки обнаружения: [первый кадр + 1 с, последний кадр - 1 с] записи, одинаково для всех вариантов.
- Допустимый интервал: 272,7–1500 мс (40–220 уд/мин).
- **Эталон.** контактная волна, равномерная сетка: N точек между первой и последней меткой записи, линейная интерполяция (как в bpm_reference); MSPTD (V2) на волне без фильтрации, затем параболическое уточнение (refine_peaks_subsample).
- **V0** — онлайн-цепочка как есть: пики окна -> _update_ibi_log; удар учтён, если позже последнего учтённого. `detect_pulse_peaks`: distance = fps*60/220, prominence = 0.25*std окна, свёртка чередования при отношении >= 1.6; края окна 1 с; разрыв ряда при > 3000 мс. ВСР: hrv_time_domain с ectopic_artifact_mask(0.4) по ВСЕМУ ряду _ibi_log записи (на UBFC онлайн-цепочка ВСР не выдаёт: нужно >= 120 с накопления).
- **Непрерывный сигнал (V1–V3).** POS, окно 1.6 с, реконструкция наложением; preprocess_signal с cfg.filt (детренд Тарвайнена lambda=3542, Баттерворт 4-го порядка 0.7-4.0 Гц нулевой фазы, z-нормировка) на всей записи. Частота: (N-1)/span по меткам кадров записи. Валидность: лицо найдено и ROI валиден по extract_rois (без онлайн-проверки стабильности числа пикселей); пропуски заполняются fill_gaps; удары в провалах длиннее 15 кадров отбрасываются. Края записи — 1 с.
- **V1** — detect_pulse_peaks + refine_peaks_subsample на непрерывном сигнале каждой области.
- **V2** — MSPTD, перенос ppg-beats msptd_beat_detector.m (коммит a1f3bef): окно 6 с, перекрытие 20 %, коррекция пика ±50 мс; понижение частоты — нет (do_ds = 0 в исходнике); уточнение — refine_peaks_subsample (то же, что у V1). Отличия от исходника, неизбежные при переносе: длина окна округляется до целого числа отсчётов, окно коррекции обрезается границами (в Matlab оба случая — ошибка индексации).
- **V3** — V2 на одной области на всю запись: argmax среднего по окнам SNR области (snr_by_roi_db онлайн-цепочки, конечные значения).
- **ВСР.** RMSSD и pNN50 — по разностям смежных интервалов (оба допустимы, общий удар); SDNN — по допустимым интервалам; эктопический фильтр не применяется (кроме V0, см. выше); видео и эталон на общем отрезке [max(первых ударов), min(последних ударов)].
- Швы: интервал _ibi_log, удары которого учтены в окнах с разными областями; дыра — элемент _ibi_log, у которого pt - gap не совпадает с pt предыдущего (допуск 1 мс); повторная детекция — |Δt| одного удара в соседних окнах (сопоставление ±100 мс).
- Неправдоподобный эталон: |ЧСС по эталонным ударам - медиана основного эталона частоты записи| > 5 уд/мин.

## Ограничения эталона

- Во втором подмножестве UBFC шаг временно́й оси контактного сигнала неравномерен (0,010–0,223 с).
  Такой эталон годится для подсчёта ударов, но слишком груб для RMSSD с точностью до миллисекунд.
  Поэтому ниже метрики приведены для обоих подмножеств, но **основным для RMSSD, SDNN и pNN50
  считается первое** (8 записей, 62,5 Гц, равномерная сетка); второе — отдельно, с этой пометкой.
- **Систематический сдвиг видео относительно эталона.** Удары видео приходят раньше эталонных:
  медианный по записям сдвиг до ближайшего эталонного удара -134 [-183–-60] мс (V3), а доля
  ударов V3 в пределах ±150 мс от ближайшего эталонного — 0,385 [0,193–0,619]. Пульсовая волна
  доходит до лица раньше, чем до пальца с датчиком, и форма волны после полосового фильтра
  другая. При заданном допуске ±150 мс часть верно найденных ударов поэтому не сопоставляется:
  чувствительность, точность и F1 ниже отражают этот сдвиг, а не только качество обнаружения.
  От сдвига не зависит **отношение числа найденных ударов к эталонному** — оно приведено в
  таблице. Ошибки интервала и ВСР считаются по разностям времён и от постоянного сдвига не
  зависят, но ошибка интервала считается только по сопоставленным ударам. Допуск не менялся.
  Сдвиг по записям — `video_reference_offset.csv`.

## Диагностика швов: гипотезы раздела 1

**1. Детектор внутри окна слишком разрешающий.** Онлайн-цепочка находит больше ударов, чем
эталон (столбец «ударов / эталон» у V0). Тот же `detect_pulse_peaks`, применённый один раз к
непрерывному сигналу (V1), даёт отношение заметно ближе к 1, MSPTD (V2, V3) — около 1.
Фаза лишних ударов внутри эталонного цикла, доли по десятым цикла, %:

| вариант | 0–0,1 | | | | | | | | | 0,9–1 |
|---|---|---|---|---|---|---|---|---|---|---|
| V0 | 1 | 1 | 3 | 8 | 12 | 18 | 25 | 20 | 7 | 3 |
| V1 | 0 | 0 | 4 | 10 | 14 | 22 | 28 | 20 | 1 | 0 |
| V2 | 0 | 0 | 2 | 8 | 14 | 23 | 30 | 22 | 2 | 0 |

Распределение фазы смешано с систематическим сдвигом (зона 0,6–0,9 — это и верные удары,
не попавшие в допуск), поэтому место выемки по нему не локализуется.
Вердикт: лишние удары подтверждены; по сравнению V0 и V1 бо́льшая их часть возникает не в
самом детекторе, а при его применении по окнам.

**2. Швы между окнами.** Повторная детекция одного удара в соседних окнах: медиана сдвига
0,23 [0,16–0,37] мс, p95 37,05 [18,34–50,07] мс по записям.
Удар, принятый ближе 273 мс к предыдущему (вставка лишнего удара; интервал не пишется, но
указатель сдвигается): 38 [35–44] за запись; отклонённых длиннее 1,5 с —
0 [0–0], разрывов > 3 с — 0 [0–0].
Вердикт: сдвиг граничного удара между окнами обычно меньше миллисекунды, но в хвосте до десятков мс;
вставка лишних ударов на швах подтверждена.

**3. Переключение области.** Переключений за запись 11 [6–16]; интервалов,
пересекающих переключение, 5 [2–7]. Ошибка интервала на переключении
22,15 [13,32–42,76] мс против 26,70 [15,89–37,20] мс в остальных;
разность по 26 записям: медиана 1,11 мс, больше на переключении у
13 из 26, критерий Уилкоксона p = 0,82.
Задержки прихода пульса между областями — ниже (около 16–18 мс между лбом и щеками).
Вердикт: различие ошибки на переключениях в данных не обнаруживается; ожидаемый вклад —
порядка задержки между областями, ниже типичной ошибки интервала.

**4. Дыры в ряду.** Дыр в `_ibi_log` за запись 30 [27–36] (в основном после
отброшенных коротких интервалов, см. п. 2). RMSSD с разностями через дыры
115,91 [70,94–189,75] мс, без них 123,10 [71,75–189,15] мс; разность: медиана
0,76 мс, больше с дырами у 26 из 50 записей.
Вердикт: механизм подтверждён (разности через дыры входят в RMSSD), величина эффекта мала
по сравнению с общей ошибкой RMSSD онлайн-цепочки.
