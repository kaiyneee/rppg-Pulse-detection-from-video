# Поведение SQI на вырожденных входах: данные прогона

Прогон 11 условий по 50 записям UBFC-rPPG, 32153 окон (2923 на условие).
Отчёт содержит только данные и результаты проверок — без выводов о гипотезе,
ради которой прогон затевался.

## Воспроизведение

```bash
PYTHONPATH=src venv/bin/python3 benchmark/degenerate.py --data-dir ~/Downloads
PYTHONPATH=src venv/bin/python3 benchmark/degenerate_acceptance.py
```

Приоритетная проверка детектора мерцания (задача 0, 5 записей):

```bash
PYTHONPATH=src venv/bin/python3 benchmark/degenerate.py --task0
```

Сводки можно пересобрать из готового `windows.csv`, не повторяя прогон:
`benchmark/degenerate.py --summarize-only`.

Прогон занял 7,25 ч (550 запусков, медиана 29,4 с на запуск). Запускать под
`caffeinate -i`: пять запусков выпали в 1000–4000 с, когда машина уходила в сон
или троттлинг. На результаты это не влияет — повторный прогон тех же пар даёт
те же байты, — но на планирование времени влияет.

Окружение: macOS-27.0-arm64-arm-64bit, python 3.9.6,
mediapipe 0.10.35, numpy 2.0.2,
scipy 1.13.1, opencv 5.0.0.
Полный дамп конфига, хеш исходников и seed — в `run_meta.json`.

### Ловит ли проверка условия B1f и B2f

**`B1f` (мерцание только по лицу, a = 0,003): не ловит, 0 флагов из 2923 окон.**
Фон не дошёл до детектора ни разу. Измерено на записи 10: СКО сырого фонового
сигнала 0,0288 уровня при пороге 0,5. Мерцание наложено только на маску кожи,
фон физически не модулирован — ловить нечего и при отключённом пороге.

**`B2f` (то же, a = 0,015): 31 флаг из 2923 окон (1,06 %), и все на записях 6
(27 флагов) и 5 (4 флага).** Это не обнаружение мерцания на лице, а утечка
маски: на этих двух записях `roi.build_skin_mask` относит к коже ВЕСЬ фоновый
патч (доля маски в патче 1,000), поэтому мерцание «по лицу» накладывается и на
фон. Амплитуда там 1,4 уровня на записи 5 и 1,8 на записи 6 — выше порога 0,5,
фон доходит до детектора и совпадает с лицевой частотой. Для сравнения, у
записей 8 и 11 доля маски в фоновом патче 0,000, у subject1 — 0,015, и флагов
там нет.

Для полноты: `B1w` (мерцание на весь кадр, a = 0,003) тоже даёт 0 флагов. Фон
там модулирован, СКО 0,3107 уровня, что совпадает с расчётом 0,003 × 145,4 / √2
= 0,3084, но это ниже порога 0,5, и сигнал отбрасывается до сравнения частот.

## Результаты проверки приёмки

1. **Регрессия на контроле — ПРОЙДЕН.** `G0`: 2923 окна (точное совпадение),
   MAE 1,671 против опубликованных 1,67 (отклонение 0,04 % при допуске 1 %),
   покрытие 0,9890 против 0,989. Записей с расхождением сверх допуска нет.
2. **`A1`, доля публикаций равна нулю — НЕ ПРОЙДЕН.** Опубликовано
   125 окон из 2923 (4.3%), затронуто
   48 записей из 50. Окна сосредоточены в
   начале записей: индекс 0 — 42 окон, индекс 1 — 20,
   индекс 2 — 7, индекс 3 — 9. Порог и логика SQI не
   менялись (это запрещено разделом 2 задания), поэтому критерий оставлен
   непройденным. Механизм установлен отдельным измерением: кадры `A1`
   побитово идентичны (проверено), но MediaPipe в видеорежиме на 299 кадрах
   из 300 возвращает слегка разные точки — максимальный сдвиг 3,3·10⁻³ в
   нормированных координатах, около 2 пикселей. Полигон ROI смещается, состав
   усредняемых пикселей меняется, и средняя зелёная яркость лба колеблется с
   СКО 0,14 и размахом 1,06 уровня. Этого хватает, чтобы у 329 окон
   из 2923 появился конечный спектральный SNR (у остальных `-inf`), а
   125 окон прошли все гейты. Медианная оценка на них — 46,5 BPM.
3. **Число окон на запись совпадает между условиями — ПРОЙДЕН.** Все 50
   записей согласованы: 2923 окон в каждом из 11 условий.
4. **Колонки на месте и не пусты целиком — ПРОЙДЕН.** Все 21 колонка
   присутствует, полностью пустых нет.
5. **Повторный прогон даёт те же байты — ПРОЙДЕН на подвыборке.**
   СОВПАДАЕТ побитово на подвыборке: 8 пар (запись, условие), 424 строк. Подвыборка задевает все нетривиальные пути: `A2` (генератор
   шума — проверяет фиксацию seed), `B1f` (маска лица), `D1` (подмена выбора
   ROI), `G0` (подлинное видео). Полный семичасовой прогон повторно не
   запускался. Дополнительное свидетельство: отдельный запуск задачи 0
   (другой процесс, другая подвыборка, режим `--task0`) дал 945 строк,
   совпадающих с соответствующими строками основного прогона все 945 из 945.

## Что пришлось решить самостоятельно

1. **Двухпроходный офлайн-режим включён для ВСЕХ условий.** Опубликованные
   числа, с которыми сверяется пункт 1 приёмки, получены именно в нём; без
   него контроль не сошёлся бы.
2. **`flicker_score` = SNR фонового ROI в дБ** — непрерывная величина, которую
   порогует детектор. `flicker_flag` = `flicker_suspected`, то есть
   подтверждённое несколькими окнами подряд решение, а не разовый кандидат.
3. **`sqi_snr` = нормированная SNR-компонента ПОСЛЕ штрафа за гармоническую
   путаницу** — ровно то, что входит в взвешенную сумму. Штраф выгружен
   отдельной колонкой `harmonic_plausibility`; значение до штрафа добавлено в
   `SQIResult.snr_score_raw`.
4. **`harmonic_plausibility_fail_rate` = доля окон со значением < 1,0**, то
   есть где штраф вообще применён.
5. **Медианный кадр для `A1` считается по каждому 10-му кадру** — полный стек
   записи это около 1,8 ГБ в памяти. σ шума для `A2` — медиана по пикселям и
   каналам от их временно́го СКО (медиана, а не среднее: среднее утягивают вверх
   пиксели на границе лица, где дисперсия отражает движение, а не шум сенсора).
6. **Растушёвка маски лица** — гауссиан с σ = 18/3 = 6 пикселей, то есть
   переход около 18 пикселей.
7. **Частота наложения для `B3`** = (медианный эталонный BPM записи + 25)/60,
   где медиана берётся по регулярной сетке окон с шагом 1 с, тем же способом,
   что и эталон.
8. **`D1` переносит ROI на ТРИ разных свободных угла**, а не на один общий
   патч: с одним патчем межзонное согласие было бы тождественно единичным по
   построению обёртки, а не по поведению индекса. Геометрия повторяет
   `roi.build_background_roi_mask`; маска кожи к фоновым патчам не применяется,
   как и в самом `roi.py`. Если свободных углов меньше трёх, патчи повторяются.
9. **`C2`**: в системе нет ffmpeg и нет brew, поэтому поставлен пакет
   `imageio-ffmpeg` со статическим бинарником (ffmpeg 7.1, libx264) ТОЛЬКО в
   venv; `requirements.txt` не изменён. Параметры: `-crf 45 -preset medium
   -pix_fmt yuv420p -fps_mode passthrough`, число потоков зафиксировано на 4
   ради побитовой воспроизводимости. Проверено, что число кадров сохраняется.
10. **Seed** = `crc32(record_id|condition)`, а не встроенный `hash()`: тот
    рандомизируется при каждом запуске интерпретатора, и повторный прогон давал
    бы другой шум.
11. **`run_meta.json` без хеша коммита**: рабочая копия не под git. Вместо
    коммита — sha256 по всем `src/**/*.py`.
12. **Перцентили считаются методом ближайшего значения**, без интерполяции:
    интерполяция даёт `nan` на выборках с `-inf`, и условие, где пик не найден
    ни разу, показывало бы пустые квартили вместо `-inf`.
13. **Проверка численной части наложения дала результат, расходящийся с
    формулировкой задания.** Задание предполагает, что без шума сенсора
    квантование уничтожит субразрядную модуляцию. Измерение
    (`scripts/check_degrade_dither.py`): с шумом модуляция 0,300 %
    восстанавливается как 0,277 %, без шума — как 0,472 %, то есть не
    исчезает, а искажается в полтора раза. Дизерингом работает разброс яркости
    между пикселями маски, а не только временной шум. Условия с мерцанием всё
    равно построены поверх `A2`, как требует задание.
