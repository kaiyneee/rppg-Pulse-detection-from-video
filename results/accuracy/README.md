# Точность оценки пульса: что найдено и что изменено

Этап после исправления частоты дискретизации (`results/fs_fix/`). Цель —
понять, где теряется точность, и исправить структурно, а не подчищать
отдельные ошибки.

## Итог

Новая конфигурация — **периодограмма полного окна (`frequency_method = fft`)
и усреднение нормированных спектров трёх областей лица
(`roi.spectral_combination = "spectral_mean"`)**.

| часть UBFC | MAE, эталон по полному окну | MAE, «свой» эталон | промахи > 5 уд/мин | покрытие |
|---|---|---|---|---|
| разработочная (20) | 1,700 → **1,146** | 1,301 → **1,172** | 4,12 % → 2,09 % | 98,1 % → 98,8 % |
| тестовая (30) | 1,755 → **1,238** | 1,388 → **1,260** | 4,33 % → 2,74 % | 99,5 % → 99,5 % |
| все (50) | 1,733 → **1,201** | 1,353 → **1,225** | 4,25 % → 2,48 % | 99,0 % → 99,2 % |

Попарно по записям (лучше / хуже, знаково-ранговый критерий Уилкоксона):

| часть | эталон по полному окну | «свой» эталон |
|---|---|---|
| dev | 20 / 0 из 20 (p = 1.9e-06) | 16 / 3 из 20 (p = 8.3e-03) |
| test | 29 / 1 из 30 (p = 1.3e-08) | 23 / 3 из 30 (p = 1.4e-04) |

Решения принимались только по разработочной части (20 записей, разбиение
зафиксировано заранее и не зависит от ошибок, см. `benchmark/experiments.py`).
Тестовая часть вскрыта один раз, для уже выбранной конфигурации: выигрыш там
практически тот же, что на разработочной, признаков подгонки нет. Контроль:
штатный вариант на всех 50 записях даёт «свой» MAE 1,353 — ровно число первой
статьи после исправления частоты.

**Умолчания в коде не изменены.** Новая конфигурация включается двумя
параметрами (см. «Как включить»); решение о смене умолчаний — за вами,
потому что оно меняет поведение конвейера, на котором получены результаты
первой и второй статей.

## Почему два эталона

Три разумных определения «пульса за окно» по контактной волне расходятся
между собой с медианой около 0,9 уд/мин — столько же, сколько медианная
ошибка самой программы. Во втором подмножестве UBFC пульс заметно меняется
внутри окна, и результат зависит от того, какие именно секунды брать. Поэтому:

- **эталон по полному окну** — общее мерило для всех вариантов: пульс за все
  10 секунд окна, той же процедурой, что в статье, но со спектром по всему окну;
- **«свой» эталон** — та же процедура, что у оценки варианта (философия задачи
  53): у штатного Уэлча это эталон статьи, у новой конфигурации — периодограмма
  контактной волны. Самый строгий критерий; новая конфигурация выигрывает и по нему.

Синхронизация видео и контактного датчика проверена: ошибка минимальна ровно
при нулевом сдвиге окна эталона, сдвиг на ±1 с стоит ~0,4 уд/мин.

## Находки

**1. Штатный оценщик выбрасывает последние 2 секунды каждого окна.** Уэлч с
сегментом 8 с и перекрытием 50 % в окне 10 с помещает ровно один сегмент:
усреднения нет, последние ~2 с не используются. Проверено напрямую: порча
этих отсчётов шумом в 100 раз сильнее сигнала не меняет спектр ни на бит.

**2. Выигрыш даёт именно сочетание двух изменений.** Только полное окно:
свой MAE 1,301 → 1,439 (узкие, но шумные пики, выбор одного ROI цепляет
ложный). Только усреднение ROI: 1,301 → 1,323. Вместе: 1,301 → 1,172.
Шум разных зон лица независим, пульс общий — среднее подавляет случайные пики.

**3. Остаточная ошибка.** Медиана ошибки по окну 0,62 уд/мин. Из грубых
промахов на разработочной части (19 из 1140 окон) в 10 истинного пульса в
спектре нет вообще — сигнал его не содержит, выбор пика тут бессилен; ещё в
8 истинный пик есть, но второй-четвёртый по высоте, примерно вдвое ниже ложного.

## Что не сработало (проверено на разработочной части)

| идея | результат |
|---|---|
| отбеливание спектра (`peak_selection = "whitened"`, было в коде непроверенным) | MAE 1,301 → 2,667, промахов втрое больше |
| многооконный метод (DPSS) | ошибается даже на чистой синусоиде: плоская вершина пика |
| учёт второй гармоники при выборе пика | +0,016 при малом весе, октавные ошибки при большом |
| CHROM, GREEN, PCA вместо POS; смешивание методов | POS лучший; смеси хуже |
| 11 мелких участков кожи вместо трёх областей | 1,230 и 1,220 против 1,201 |
| взвешивание областей по чистоте спектра | 1,237 против 1,201 |
| отслеживание пика алгоритмом Витерби | −0,03 по MAE ценой лишних промахов |
| короче окно POS (1,0 с вместо 1,6 с) | MAE лучше, промахов больше — не принято |

## Решение за вами: порог публикации

Сейчас публикуется ~99 % окон (порог SNR −9,5 дБ очень мягкий). Доля
мощности у главного пика объединённого спектра хорошо отделяет плохие окна:
почти 80 % грубых промахов попадают в нижние 10 % по этой мере.
Разработочная часть, все окна:

| покрытие | MAE | промахи > 5 |
|---|---|---|
| 100 % | 1,38 | 2,41 % |
| 95 % | 0,96 | 0,64 % |
| 90 % | 0,91 | 0,57 % |
| 80 % | 0,84 | 0,32 % |

Штатный SQI работает почти так же (95 % → MAE 0,98, промахи 1,09 %). SQI —
предмет второй статьи, поэтому молча я его не меняла.

## Как включить

```python
from rppg.config import PipelineConfig, FrequencyMethod
cfg = PipelineConfig()
cfg.frequency_method = FrequencyMethod.FFT
cfg.roi.spectral_combination = "spectral_mean"
```

`scripts/eval_ubfc_subject.py` считает эталон методом из конфига, поэтому
при смене метода эталон автоматически становится «той же процедурой на том
же отрезке».

## Изменения в коде

- `src/rppg/config.py` — `ROIConfig.spectral_combination` (по умолчанию
  `"best_snr"`, прежнее поведение);
- `src/rppg/signal/frequency.py` — публичная `select_peak_from_spectrum`
  (та же логика непрерывности и ограничения скорости, что внутри оценщиков);
- `src/rppg/pipeline.py` — режим `spectral_mean` в `_compute_estimate`;
- `tests/test_spectral_combination.py` — 6 тестов; весь набор: 100 + 6 проходят.

Воспроизведение из кэша при умолчаниях совпадает с полным прогоном побитово
(все 50 записей, 2923 окна).

## Инструменты

- `benchmark/trace_cache.py` — кэш сигналов с лица; воспроизведение побитово
  совпадает с полным прогоном и в ~50 раз быстрее (весь UBFC за 13 с);
- `benchmark/experiments.py` — сквозная оценка вариантов, разбиение dev/test;
- `benchmark/spectral_dataset.py`, `estimator_lab.py`, `offline_eval.py`,
